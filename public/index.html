Why Naelix

Built for teams shipping calling as a feature, not a product.

Authentication

Two headers, no user tokens.

Naelix authenticates the service calling it, not the end user placing the call. Send your API key and secret key on every request — Naelix trusts the user identity you pass alongside them, the same way you already trust your own session layer.

  • X-Api-Key — identifies your integration.
  • X-Secret-Key — proves it's really you. Never expose this in a browser or mobile app.

Base URL for every request — this same origin:

API reference

Every endpoint, grouped by resource.

The same surface Swagger documents interactively — this is the quick-scan version. meetings covers group calls, calls covers 1:1 — see the Endpoint surface note above for why they're separate.

Calls apiKey + secretKey

POST/callsCreate a 1:1 call room. Body: callerId (required), id, mode (video | audio_only).
GET/calls/:idGet a call's current state.
POST/calls/:id/endEnd a call for both participants.

Meetings apiKey + secretKey

POST/meetingsCreate a group meeting room. Body: hostId (required), id, mode, waitingRoomEnabled, chatEnabled, reactionsEnabled, screenShareEnabled.
GET/meetings/:idGet a meeting's current state.
POST/meetings/:id/endEnd a meeting for every participant.
DELETE/meetings/:idRemove a meeting's in-memory record.

Moderation apiKey + secretKey

POST/meetings/:id/muteMute a participant.
POST/meetings/:id/kickRemove a participant (alias of remove).
POST/meetings/:id/removeRemove a participant from the meeting.
POST/meetings/:id/promotePromote a participant to co-host.
POST/meetings/:id/demoteDemote a co-host back to participant.
POST/meetings/:id/lockLock the meeting against new joins.
POST/meetings/:id/unlockUnlock the meeting.

Participants apiKey + secretKey

GET/participants/:meetingIdList a meeting's current participants.

Developer & ops public, no auth

POST/developer/api-keysGenerate a trial (apiKey, secretKey) pair — what the button above calls. Rate-limited per visitor.
GET/healthService health, mediasoup worker stats, meeting counts.
GET/metricsPrometheus metrics (plain-text exposition format).
Real-time signaling

Socket.IO, not REST, for the call itself.

REST creates and manages rooms; the actual join/produce/consume flow runs over Socket.IO on two namespaces — /calls (1:1, no moderation) and /meetings (group, full moderation surface). Connect with auth: {'{'} apiKey, secretKey, userId, displayName {'}'}, then emit joinRoom with an ack callback to get back rtpCapabilities and start producing/consuming media.
